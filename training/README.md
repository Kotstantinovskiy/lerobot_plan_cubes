# Обучение

SmolVLA дообучается штатным `lerobot_train` из форка `lerobot_cubes` (LeRobot 0.4.4); скрипты здесь задают настройки проекта и повторяют подготовку на Linux-машине с NVIDIA GPU. Результаты пишутся в `outputs/train/<run-name>`, оценки — в `outputs/eval/<run-name>` (не в Git).

| Скрипт | Что делает |
| --- | --- |
| `setup_linux.sh` | клонирует форк рядом с репозиторием (`../lerobot_cubes`), создаёт `.venv` на Python 3.12, ставит `lerobot[smolvla]` и `gdown` |
| `fetch_dataset.sh` | скачивает архив датасета с Google Диска (`ep40` — 40 эпизодов, по умолчанию; `pilot20` — пилот), склеивает части, сверяет SHA-256 и распаковывает в `data/color_cubes_wrist1080` |
| `train.py` | запускает обучение с настройками проекта; `--dry-run` показывает команду |
| `lerobot_train_resized.py` | `lerobot_train`, в котором кадры уменьшаются до входа SmolVLA ещё в процессах загрузки (см. ниже); его запускает `train.py` |
| `eval_offline.py` | проверяет чекпойнт на записанных кадрах без робота: ошибку действий и реакцию на смену цвета в команде |
| `eval_checkpoints.sh` | ждёт каждый чекпойнт запуска и прогоняет на нём `eval_offline.py` |

## Подготовка Linux-машины

Нужны NVIDIA GPU, `git` и [uv](https://docs.astral.sh/uv/). Из корня репозитория:

```bash
bash training/setup_linux.sh
source ../lerobot_cubes/.venv/bin/activate
bash training/fetch_dataset.sh
```

`fetch_dataset.sh` скачивает через `gdown` папку Google Диска `color_cubes_40ep_2026-10-26` (с аргументом `pilot20` — `color_cubes_pilot20_2026-10-25`), поэтому у папки должен быть доступ «все, у кого есть ссылка», хватает права на чтение. `gdown` видит в одной папке не больше 50 файлов, поэтому 62 части архива на 40 эпизодов лежат в двух подпапках; скрипт находит их рекурсивно и склеивает по порядку имён. Если в `data/color_cubes_wrist1080` уже лежит другой датасет (например, пилот), он переносится в `data/color_cubes_wrist1080_<N>ep`. Уже скачанные части не качаются повторно; адрес папки и каталог загрузки меняются через `FOLDER_URL` и `WORK`.

**devbox01:** в `~/.bashrc` весь HTTP(S) направлен в `127.0.0.1:12336` — обратный SSH-туннель к tinyproxy на Mac. Через него PyPI отдавал 0,28 МБ/с, напрямую — 16 МБ/с, поэтому установку, загрузку и обучение (оно скачивает конфиг SmolVLM2 с Hugging Face) там запускай без прокси: `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY <команда>`.

## Запуск обучения

```bash
mkdir -p outputs/train
tmux new -s train
python training/train.py --gpu 0 --run-name smolvla-pilot20 2>&1 | tee outputs/train/smolvla-pilot20.log
```

По умолчанию: `lerobot/smolvla_base`, батч 64, 20 000 шагов (~170 эпох пилота), чекпойнт каждые 2500 шагов, `min(32, число ядер)` процессов загрузки. Обучается только action expert (100 млн из 450 млн параметров), VLM и энкодер изображений заморожены — как в штатном рецепте SmolVLA; `--full-finetune` обучает всю модель. Отличия от команды в `TRAIN.md` архива:
- **камеры переименованы** `top` → `camera1`, `wrist` → `camera2`, как в предобучении `smolvla_base`;
- **аугментация изображений включена без сдвига оттенка и резкости.** Штатный `hue ±0.05` уводит красный к оранжевому, а задача задаётся цветом кубика. Резкость на кадрах 1080p + 720p стоила 0,3 с на сэмпл — в 8 раз больше остальных вместе — и GPU простаивал. Остаются яркость, контраст, насыщенность и поворот ±5° со сдвигом 5%. `--no-augment` отключает всё;
- **LR-расписание** затухает ровно за `--steps` шагов (в конфиге SmolVLA — за 30 000 независимо от числа шагов);
- **кадры уменьшаются в процессах загрузки.** SmolVLA первым делом сжимает каждый кадр до 512×512 (`resize_with_pad`, bilinear, поля нулями). `lerobot_train_resized.py` вызывает ту же функцию сразу после аугментации, и на входе модели получается то же самое (проверено: разница 0,0; loss повторяет запуск без обёртки), но сэмпл весит 6 МБ вместо 36 МБ. Без этого поток pin-memory копировал 2,3 ГБ на батч и держал обучение на 1,3 с/шаг. Чекпойнт обычный: на инференсе политика получает полные кадры и сжимает их сама.

`--episodes 0,1,2` ограничивает обучение этими эпизодами, например чтобы отложить по эпизоду каждого цвета для проверки. Аргументы после `--` передаются `lerobot_train` без изменений. Продолжить прерванный запуск с последнего чекпойнта: `python training/train.py --run-name smolvla-pilot20 --resume`.

Замеры на devbox01, одна H200, пилот из 20 эпизодов: шаг GPU 0,47 с, загрузка 0,2 с, итого ~0,66 с/шаг, 20 000 шагов — около 4 часов; ~16 ГБ памяти GPU. Чекпойнт — 1,2 ГБ весов плюс состояние оптимизатора.

## Проверка без робота

```bash
python training/eval_offline.py --policy outputs/train/smolvla-pilot20/checkpoints/last/pretrained_model
```

Для кадров через каждую секунду политика предсказывает пачку из 50 действий с командой каждого цвета при одном и том же шуме. В таблице строка — цвет кубика в эпизоде, столбец — цвет в команде, значение — средняя разница с записанными действиями в единицах суставов датасета. Если с чужим цветом ошибка почти такая же, как с правильным, а пачка почти не сдвигается, модель не читает цвет в команде. На эпизодах из обучения это показывает только качество подгонки.

Точка отсчёта — чекпойнт после 200 шагов: ошибка 7,9 с правильным цветом и 8,0 с чужим, сдвиг пачки от смены цвета 0,9, то есть цвет пока игнорируется.

Оценивать каждый чекпойнт по мере сохранения (во втором окне `tmux`; останавливается после последнего шага):

```bash
bash training/eval_checkpoints.sh smolvla-pilot20 2>&1 | tee outputs/eval/smolvla-pilot20.log
```

## Перенос на Mac с рукой

Нужна только папка `pretrained_model` выбранного чекпойнта:

```bash
mkdir -p outputs/train/smolvla-pilot20
scp -r <машина>:<репозиторий>/outputs/train/smolvla-pilot20/checkpoints/020000/pretrained_model outputs/train/smolvla-pilot20/
HF_HUB_OFFLINE=1 python inference/run_policy.py --policy outputs/train/smolvla-pilot20/pretrained_model --color red --seconds 20
```
